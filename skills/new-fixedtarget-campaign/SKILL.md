# new-fixedtarget-campaign

Goal: a prepared fixed-target campaign (one job per measured point, then merge, ResBos2 `GetFixed`, and a final table job).

Read first: `local/env.md` (run `discover-environment` if missing), `rules/q_le_ecm.md`, `rules/legacy_output_by_lto.md`, `rules/pdf_name_trap.md`, `rules/cluster_etiquette.md`,
`docs/FIXED_TARGET_WORKFLOW.md` (physics and commands), `recipes/fixedtarget-dy.md`.

Remote mode (`local/remote.conf` exists): edit the `.ini` on the laptop, `python3 scripts/remote.py push`, and run every cluster command as `python3 scripts/remote.py run -- <command>` (table in `AGENTS.md`, setup in `docs/REMOTE.md`). Paths are cluster paths.

## What the chain does
Per target (pp, pd, or the single one): Legacy `LTO=-1` (LO), `LTO=3` and `LTO=1` on a qT grid (NLO after a qT integration), ResBos2 `GetFixed` for resNLO (W321),
then a final job: Yao's ROOT macro `scripts/getnlo/getnlo.C` per point (via `scripts/run_getnlo.sh`) and `scripts/make_fixedtarget_tables.py` (needs ROOT and Python with numpy).

## Steps

1. **Pin the request**: dataset (the driver knows `e605`, `e866ppxf`, `e866f`, `e906aF` in `FT_DATASETS` with their ECM, beam, neutron fraction and Jacobian), PDF set, and `compute`
   (`LO, NLO, resNLO`; the final K-factor table needs all three). A new dataset is a change to `run_process.py` and `templates/FixTargetTables/`: see "Another fixed-target set" in `docs/CAMPAIGNS.md`,
   and tell the user it changes the shared toolchain (`rules/determinism.md`).
2. **Check the environment has what this mode needs**: a Legacy `main` built **without** the A0 override (so not the collider `main` unless the user confirms), ResBos2 `GetFixed`
   and its environment script, ROOT, and python3 with numpy for the final job.
3. **Start from** `examples/FT_e605_CT25NLO.ini`. Copy to `local/`, set `[paths] dest`, `[campaign] name/pdf/compute`, `[executables]`, `[fixedtarget] getfixed, resbos2_env`
   and, if the PDF name exists in two LHAPDF installs, `lhapdf_data_path`. Do not add `[energies]` or `[grids] experimental/generate`: the driver refuses them in this mode.
4. **Prepare** (no submit): `python3 run_process.py local/<name>.ini`. Check that every table row has Q <= ECM and read back the resolved inputs.
5. **Review, authorize and submit one dataset at a time.** Array tasks count against queue limits. Run `review-and-authorize`; submit with `scripts/campaign_review.py submit` only after the approval is recorded.
6. **Not automated**: the fixed-xF refinement (y(qT) < y0) and W432. If the user needs them, say so; do not improvise.
7. **After the run**: `results/<name>_LO_NLO_W321.txt` holds LO, NLO, W321 and K-factors. Compare against a reference if one exists (`data/` of the original project, or the user's own)
   and record the outcome in the recipe (`rules/unvalidated_recipes.md`).

## Notes
- ConvGrids are generated by the first `GetFixed` run for a PDF and shared; `[fixedtarget] convgrids` reuses a finished set.
- `GetFixed` returns exit code 1 even on success; the driver judges by the output row count. A "FAILED" job with a complete `.dat` is normal.
- Do not rescale outputs to match a reference. If they differ, find the cause (HOPPET version, PDF, A0 override, Jacobian).
